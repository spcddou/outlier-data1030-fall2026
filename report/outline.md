# Midterm report 填写提纲

这是结构和问题清单，不是报告正文。主题确定后，由团队用自己的语言、实际采集方法、实际数据结果和读过的文献填写。不要把候选选题、样本检查或建议图标题写成已完成的结果。

开头：Title；全体成员姓名；Affiliation；public GitHub repository URL。

## Introduction — 5 points

建议约 200 words；字数建议不是评分规则。

- 我们具体研究什么问题，为什么值得做？
- 哪些既有研究用过相同/类似数据或解决过类似问题？它们发现了什么？
- 本项目的明确范围是什么？

## Data — 10 points

建议约 300 words。

- 原始数据发布者、dataset/API URL、采集日期、日期范围。
- 实际编程采集方法、query、pagination 与筛选规则。
- 一行代表什么；原始/分析数据有多少行、多少列。
- 主要变量类型、target 定义、单位/类别。
- 缺失、重复和排除规则；data dictionary 放在哪里。

## Exploratory Data Analysis — 10 points

建议正文约 400 words，另预留约 150 words 给 captions。

- Figure 1：target 分布；一句由数据支持的 headline；caption 写单位、样本和必要处理。
- Figure 2：重要 feature 与 target 的关系；解释为什么与研究问题有关。
- Figure 3：时间变化或第二个重要 feature；解释模式与限制。
- 图型适合变量类型；坐标轴完整；必要时用 log scale。

## Problem description and potential impact — 5 points

建议约 250 words。

- Unit、prediction time、features、target；任务类型。
- 实际使用者是谁，会根据预测采取什么行动？
- 哪些 fields 在预测时不可得，因此排除？
- 该用途的适用范围、偏差和限制；关联与因果分开。

## References — 5 points

- 引用实际阅读的文章、报告、数据源及既有工作。
- References 不计入 1500-word limit；正文中的引用应对应此列表。

## Appendix — optional

- 完整 data dictionary、补充图或其他支持材料。
- TA 不看 appendix 评分；正文必须独立解释项目。

GitHub repository 另计 5 points；报告和 captions 总计 ≤1500 words。上述正文+caption 预算约 1300 words，给标题、表格和必要补充保留余量。每超出 50 words 扣 1 分。最终 PDF 存入本目录并交 Gradescope。
